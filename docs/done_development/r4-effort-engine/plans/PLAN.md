# r4-effort-engine: plan

## 1. Goal and requirements
Show which single muscles work and how hard, computed from pose, supports and loads, on both bodies. No hand-written muscle lists.

- **R1 Data** (`public/data/`, each entry with `source`): `segments.json` (Winter mass fractions and COM fraction along each segment, mapped to rig bones); `strengths.json` (Nm/kg per joint key, axis, direction `+`/`-`); `actions.json` (muscle key → actions `[joint, axis, dir, weight]`, `dir` ∈ `+ - ipsi contra`; covers every muscle `plain` in manifest, or lists it under `unmodelled` with a reason); `loads.json`, `supports.json` (Q3). Muscle key = manifest `plain` name; part id → key via the manifest (side from `part.side`). The 40 largest muscles (by part triangle count or volume, summed over heads; printed list in plans/raw/largest40.md) get `"reviewed": true` after a line-by-line check against a kinesiology source.
- **R2 Engine core** (`src/engine/`, pure TS, may import pure `src/rig/*`, never three.js): geometry from a posed skeleton (segment COMs, joint centres, body points: hand, foot ball, heel, pelvis ischial point, thorax back point, shin, shoulder); external loads (free weight = down; cable = toward pulley; machine = along track); support reactions solved from force and moment balance (minimum-norm, non-negative, active-set; two feet split by COM position); joint torques = sum of moments of all forces on the distal side; torque resolved onto each joint's own pose axes (positive-axis direction derived from `jointRotation` in `src/rig/skeleton.ts`, so signs match the FK exactly). Shoulder: long-axis component = rot; with the arm raised > 45°, torque about the trunk long axis is reported as horizontal add/abd (`hadd` axis, ±). Edge cases: no support → `balance.comOverFeet=false`, reactions zero, torques from gravity only, a `warning`; a support with negative solved force is dropped and re-solved; zero-mass input throws.
- **R3 Demand, muscles, rules** — demand = |torque| / strength for the direction needed (muscle torque opposes the external moment). Muscle level = min(1, max over matching actions of demand × weight). Extra rules, each its own file and test: scapula (arm elevation and hanging load → trapezius, serratus, rhomboids, levator), grip (hand force / grip strength → finger and wrist flexors), bracing (lumbar moment → abdominals, obliques, transversus co-contraction). `lowerBack = { momentNm (lumbar joint torque magnitude), level (÷ lumbar extension strength) }`; `balance = { comOverFeet, margin m (signed distance of the COM ground projection to the support polygon edge) }`.
- **R4 Roles and reasons** — moves between keyframes (axis changes ≥ 5°) → `does the work`; demand without motion → `holds you still`; best action weight < 0.6 → `helps`. Reasons are structured (`{kind:'joint', joint, axis, dir, demand}` or `{kind:'rule', rule, value}`) and turned into words by `explain.ts` ("Bends the left elbow against 6 kg at the hand", "Keeps the trunk upright: the load pulls it forward").
- **R5 Wiring** — Move: live effort for the current pose, supports from the pin, a hand-load kg field (default 0). Player: effort from the variant's keyframes, props → loads/supports, kg per load editable; muscle colours from levels and roles; delete `provisional_muscles.json` and every `muscles` block (and `extract_prototype.mjs` stops emitting them). Muscle panel (one component used by both): top muscles, level bar, role, reason in words, lower-back moment, balance warning, the limits text (static; ignores speed, momentum, fatigue, individual differences; estimates) and sources. Phone 390×844: panel in the existing bottom sheet, the body never covered. Both sexes.

### 2b. Clarifications (binding; critic round 1)
1. **Joint keys.** strengths.json and actions.json use sideless keys (`elbow`, `shoulder`, `hip`, `knee`, `ankle`, `wrist`) and the engine resolves them: `<key>_l` / `<key>_r` by the muscle part's side; a `center` part (Diaphragm, Iliocostalis colli) acts on both sides, `ipsi` = both sides' own side, `contra` = ignored (no contra action). Midline joints (`lumbar`, `thoracic`, `neck`, `head`) are used as is. `ipsi` = pose axis direction toward the muscle's own side (side + = body left, so a left muscle's ipsi side-bend is `+`, right is `-`; for `twist`/`turn` ipsi = turn toward the muscle's own side, same signs; `contra` the reverse). Excluded from strengths: `pelvis` (root) and `scapula_*` (derived). Every other joint axis in joints.json needs `+` and `-`. `hadd` is an engine-only axis (horizontal adduction `+`/abduction `-` of the shoulder, torque about the trunk long axis when the arm is raised > 45°); strengths and actions may use it, joints.json does not list it, tests allow it.
2. **Largest 40.** Source = the muscle pack in public/data/body (per-part vertex/triangle counts from the manifest `packs`/arrays; builder finds the layout from tools/pipeline/v5/FORMAT.md). Method: sum triangle counts over every part with the same `plain` (all heads, both sides), rank, take the top 40. Written to plans/raw/largest40.md with the counts.
3. **Props.** All 20 prop names in plans/raw/variants.md. `loads.json`: bar 20 kg at `hands` (free), dbL/dbR 8 kg at `hand_l`/`hand_r`, bucket 10 kg at `hands`, bucketR 10 kg at `hand_r`, bagL/bagR 5 kg at `hand_l`/`hand_r`, box 10 kg at `hands`, mop 1 kg at `hands`, handle (cable/pushdown/pulldown/row) a `cable` 15 kg `toward` the pulley point (row: forward-down; pulldown: up; pushdown: up; overhead triceps: down-behind) at `hands`, legpress `machine` 40 kg along the track at `foot` ball points, pullbar/step1/step2/shelf/pad/reclineBack/reclineSeat: no load (`none`). kg = absolute, not body-relative (the player lets the user change them). Supports: seat → pelvis + both thigh midpoints (vertical up); back → thorax back point, normal +z (pad pushes forward); bench → thorax back point and pelvis (vertical); pad → forearm midpoints (preacher, vertical up, normal tilted 40° forward); reclineBack/reclineSeat → thorax back point and pelvis, normal 35° off vertical; pullbar → both hands (vertical up, hang); shelf, step1, step2, mop, box, bucket, bag*, handle, bar, dbL, dbR: none (steps/shelf are set pieces that only change the pose). Body points defined in geometry.ts: `hand_l/r` (grip point as props.ts), `foot_l/r` (ball head), `heel_l/r`, `pelvis` (ischial: pelvis head + 8 cm down), `thoraxBack` (spine_03 midpoint − 12 cm along body z), `shin_l/r` (calf midpoint), `shoulders` (both upperarm heads), `thigh_l/r` (thigh midpoint), `forearm_l/r` (lowerarm midpoint), `foot` aliases both ball points.
4. **Pins** (supports.json `pins`): `none` = no floor contact in the pin table (the seat or bench supplies it), `ground` / `flat` / `toes` = both feet (ground, flat: heel + ball per foot; toes: ball only), `toeL` / `toeR` = that ball only plus the other foot free, `hands` = both hands (hang). A missing pin = `toes` (as fromPrototype). Plank and push-up use `toes` plus the forearm/hand floor contact from the prop table: add pseudo-props `floorHands` (push-up) and `floorForearms` (plank) in supports.json and map exercises press/pushup and plank/front to them by a `variantProps` table in supports.json (a data table keyed by `exercise/variant`; the only per-variant entry allowed, supports only). `pinAt` only places the body (pull-up); it is not a support position.
5. **Types** (src/engine/types.ts, T3 owns): `Vec3=[number,number,number]`; `Force={ at: Vec3, f: Vec3, bone: string, kind: 'gravity'|'load'|'reaction' }`; `Load={ id: string, kind: 'free'|'cable'|'machine', kg: number, at: BodyPoint, toward?: Vec3, track?: Vec3 }`; `Support={ point: BodyPoint, normal: Vec3 }`; `Geometry={ sex, massKg, bones: Record<string,{ mass, com: Vec3, head: Vec3, tail: Vec3, Rw: number[] }>, point(name): Vec3, joint(key): Vec3 }`; `EffortInput={ pose: Pose, sex: 'male'|'female', massKg?: number (default 70), loads: Load[], supports: Support[], poseB?: Pose }`; `Reason = { kind:'joint', joint, axis, dir:'+'|'-', demand:number, loadKg?:number } | { kind:'rule', rule:'scapula'|'grip'|'bracing', value:number }`; `MuscleResult={ level:number (0..1), role:'work'|'help'|'hold'|'none', reasons: Reason[] }`; `EffortResult={ jointDemand: Record<string, Record<string, {plus:number, minus:number}>>, muscle: Record<number, MuscleResult> (keyed by part id), lowerBack:{momentNm,level}, balance:{comOverFeet:boolean, margin:number}, warnings: string[] }`. `explain(reason: Reason, side: 'left'|'right'|'center', loadKg?: number): string`. Rules: `scapulaRule(elevationDeg: number, handLoadN: number, side): Record<muscle plain, number>`, `gripRule(handForceN: number, massKg: number, side): Record<muscle plain, number>`, `bracingRule(lumbarMomentNm: number, lumbarStrengthNm: number): Record<muscle plain, number>`; the rules return levels 0..1 keyed by muscle plain name (the muscles come from actions.json `rules` tags; the rule files hold only the formulas). Errors: invalid input (mass ≤ 0, unknown joint) throws `Error` with a clear message; no-support is a `warnings` entry, not a throw.
6. **Roles.** Use the 5° rule on the posed keyframes (poses a and b): a joint axis "moves" if |a − b| ≥ 5° on any axis of that joint (peak to peak). `moving`/`held` stay as data for the library list but the engine does not read them. Without `poseB` nothing moves, so every working muscle is `hold`.
7. **Torque scope.** Torques are solved for every joint with strengths (lumbar, thoracic, neck, head, shoulder, elbow, wrist, hip, knee, ankle). Head/neck/thoracic follow the same method (distal subtree).
8. **Winter table.** Winter, D. A. (2009), Biomechanics and Motor Control of Human Movement, 4th ed., Table 4.1; SPEC §4 step 1 gives the start values (head and neck 8.1%, trunk 49.7%, upper arm 2.8%, forearm 1.6%, hand 0.6%, thigh 10%, shank 4.65%, foot 1.45%); COM fractions from the same table, noted "from memory, not checked against the book" if not verified. Grip strength: start value ≈ 5 N/kg body mass per hand (order of published adult grip dynamometry, "approximate, not verified"). The 70 kg default is SPEC §4 step 1.
9. **Test numbers.** T3 tests use tolerances: reactions sum to total weight within 0.5 N; seat hip and knee gravity torque magnitude < 5% of the unsupported value; back pad lumbar moment ≤ 20% of unpadded; two-foot split by COM within 2%; elbow torque for 10 kg at the hand at 90° = m·g·horizontal lever within 5% (lever from geometry). T3 tests build fixtures from the real rig.json and segments.json (T1 is finished before T3 starts).
10. **Greps.** "Provisional" checks use `provisional_muscles` and `"provisional"` in public/data/exercises.json and tasks.json only; Programs notices (`programs.json`, src/programs, style.css) are untouched. Purity check: `grep -rn "from 'three'" src/engine` → nothing. `src/ui/programs.ts` stays as is.
11. **Misc.** BASELINE.md is in this folder. docs/prompts/next.md template = the user's R4 handover prompt: T9 builds R5 from docs/PROMPTS.md "R5" and the structure in §2c below. The cdp-shot loop script is `tools/engine/shots.mjs` (T7 writes it; runs every variant of exercises and tasks on one sex and prints "opened N of 33"). The APK check uses `rm -f output/body-model-debug.apk` first. T5's `src/engine` run includes T1–T4 tests.
12. **Seat test and pins (T3 blocker, decided).** Seat test: with the seat, hip gravity torque ≤ 30% of the same pose unsupported and knee torque unchanged (the lower leg hangs past the seat, so the knee muscles still hold it; "takes the legs out" means the thigh's weight, not the shank's); also assert hip torque seat vs feet-only ≤ 10%. Pins for supports.json: a missing pin (standing; prototype default) is `flat` for SUPPORT purposes (heel + ball of both feet), although `fromPrototype` still grounds by `toes`; `toes` (explicit: plank, push-up) = balls only (the hands/forearms floor contact gives the area); `toeL`/`toeR` = heel + ball of that foot only (foot on the step, other foot free). supports.json gets a `default` pin key (= flat) that the engine uses when `pose.pin` is undefined.
13. **Case decisions (T5 blockers, decided).** (a) Case 1 (curl standing vs seated with back pad): a pad behind the back can only push the trunk forward, and a bar held in front pulls it forward as well, so the pad cannot reduce the lumbar moment; the model keeps this physics. The test asserts: same elbow flexors; standing has higher glutes and calves; erectors are within 10% of each other; and a seated pose leaned back 10° has a lower lumbar moment than upright (pad then pushes > 0 N or the moment falls ≥ 10%). SPEC §4 and the R4 report state the change (the spec's "Standing adds spinal erectors" was wrong for a pad that cannot pull). (b) Case 2 (stoop vs squat): assert lower-back moment falls and quadriceps rise (both sexes), stoop hamstrings and erectors higher than squat; glutes in the squat ≥ 90% of the stoop (the male stoop is high on glutes too: 0.330 vs 0.313); SPEC §4 wording updated. (c) Balance: the prototype keyframes do not shift the hips back, so bucket stoop and squat report comOverFeet=false (margin about −9 cm). Kept as a reported value, no assertion; the panel words it as "the centre of mass is beyond the feet in this pose"; recorded as a known gap for R5 form checks.

## 4. Interfaces
| Name | Signature | Returns | Job |
|---|---|---|---|
| `bodyGeometry` | `(skel: Skeleton, pose: Pose, segs: Segments, massKg: number)` | `Geometry` (per bone: mass, COM, joint centres, body points, parent rotations) | posed geometry |
| `solveSupports` | `(g: Geometry, loads: Load[], supports: Support[])` | `{ reactions: Force[], balance }` | step 3 |
| `jointTorques` | `(g, forces: Force[], skel)` | `Record<joint, Record<axis, number>>` (Nm, signed in pose-axis direction) | steps 4–5 |
| `effort` | `(input: EffortInput, data: EngineData)` | `EffortResult` (SPEC §4 shape + `warnings[]`) | entry point |
| `effortOverMove` | `(a: Pose, b: Pose, input, data, samples=9)` | `EffortResult` with peak levels and roles | player |
| `scapulaRule`, `gripRule`, `bracingRule` | `(g/result parts)` | `MuscleContribution[]` | step 8 |
| `explain` | `(reason: Reason, sex-neutral)` | `string` | words |

Tricky logic:
1. Axis direction: for joint key k and axis a, world axis = Rw(parent bone) · axisOf(jointRotation(k, {a: 1e-3})) / 1e-3 (rotation vector of the small rotation). Torque component = dot(muscle torque, axis). `+` demand uses strengths[k][a]['+'].
2. Muscle torque needed = −(sum of external and gravity moments about the joint centre from everything distal, incl. reactions on distal bones).
3. Supports: vertical unknown per contact point; equations Σ = total weight + vertical loads, Σ moments about x and z; min-norm via 3×3 normal equations; drop negatives and repeat. Back pad: one horizontal unknown along the pad normal, chosen to cancel the sagittal moment about the lumbar joint from the trunk-and-above (≥ 0). Horizontal loads are taken by the feet (friction), split like the verticals.
4. Seat "takes the legs out" because its contact points sit under the pelvis and both thigh COMs — no special case.

## 5. Data models
`segments.json`: `{ sources, segments: { "<name>": { bones: [..], massFraction, comFraction, from: "head|tail" } } }`. `strengths.json`: `{ sources, strengths: { "<joint>": { "<axis>": { "+": Nm/kg, "-": Nm/kg, source } } }, grip: { NperKg, source } }`. `actions.json`: `{ sources, muscles: { "<plain>": { actions: [[joint, axis, dir, weight]], rules?: ["grip"|"scapula"|"bracing"], reviewed?: true, source } }, unmodelled: { "<plain>": reason } }`; `joint` without side (`elbow`), resolved by the part's side. `loads.json`: `{ sources, props: { "<prop>": [{ at: "hand_l|hand_r|hands|shoulders|shin", kind: "free|cable|machine", kg, toward?: [x,y,z], track?: [x,y,z] }] } }`. `supports.json`: `{ sources, pins: { "<pin>": [contact] }, props: { "<prop>": [contact] } }`, contact = `{ point: bodyPointName, normal: [x,y,z] }`.

## 6. Decisions and things to avoid
| Decision | Reason |
|---|---|
| Statics only, per pose | SPEC §4 |
| Directions derived from `jointRotation` | one source of sign truth (R3 §2b) |
| Loads/supports from prop and pin tables | data, not per-variant lists |
| Level capped at 1, demand uncapped | demand can exceed strength; colours need 0..1 |
Avoid: per-exercise muscle lists, special-casing seats/pads, three.js in src/engine, new deps, network calls, unsourced claims on screen.
