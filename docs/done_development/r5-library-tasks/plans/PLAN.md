# r5-library-tasks: plan

## 1. Goal and requirements
Step 1 of R5: a searchable library of 50 reviewed exercises with correct form on the real body and real equipment, plus an everyday-task builder. All muscle effort from the engine; both sexes; phone first.

- **R1 Exercise record** (SPEC §5, flat): `public/data/exercises.json` v2 = `{ sources, version: 2, exercises: Exercise[] }`, 50 records. The 22 current variants become 22 records (ids below), grouped by `family`; 28 new records. Every record `reviewed: true` only when all its form checks pass on both sexes and its contact-sheet tile was looked at. Errors: a record with an unknown prop, pattern, posture or equipment fails the data test.
- **R2 Equipment** built in code (user decision): powder-coated steel, chrome, stitched upholstery, rubber plates, bevelled edges, real gym dimensions. Items: flat bench, adjustable bench (flat/incline/decline), squat rack, barbell with plates and collars, dumbbells, kettlebell, cable column (pulley, cable, handle/rope/bar attachments), lat machine, leg press, leg extension, leg curl, pull-up rig, plyo box, mat, resistance band. A CC0 glTF may replace an item only if it clearly looks better; then its source and licence go in equipment.json and docs/reports/R5-step1.md. Geometry, contact surfaces and colliders come from one data file (`equipment.json`) so form checks and rendering agree. Task objects (box, bucket, bag, child, suitcase, gas cylinder, furniture edge, mop, broom, chair) built the same way; the child is a stylised figure labelled "simplified".
- **R3 Equipment gate**: before any exercise uses the equipment, a contact sheet of every item (front, ¾, close-up) goes to the user; the build stops until the user approves (see §8 wave 3 → gate).
- **R4 Form checks** (pure, `src/library/form.ts`, each check its own function and test), run on every keyframe and 3 in-betweens, both sexes:
  `limits` (every axis inside joints.json, ±0.5°), `balance` (`effort().balance.margin ≥ -0.02 m` with the record's supports; fixes the R4 bucket gap), `contacts` (each support point within 3 cm of its equipment surface; hands within 4 cm of a hand-held implement's grip), `clearance` (body sample points not inside an equipment collider by > 2 cm, not below the floor by > 1 cm), `kneeOverFoot` (squat/lunge/step patterns: knee centre's side offset within the foot's width band ± 3 cm), `neutralSpine` (loaded hinge/squat/row/carry: lumbar flex ≤ param, default 20°). Output `{ id, ok, frame, value, limit, words }`. Global checks always run; the record's `formChecks[]` adds pattern checks with params.
- **R5 Exercise screen**: `#workouts/exercises` = search (name + aliases, case/accent-insensitive), filter chips (pattern, equipment, body part, posture; AND across groups, OR within), list grouped by pattern, empty-result message. `#workouts/exercises/<id>` = player: Variation select (records with the same `family`, plus "My version" if saved), load slider per load (0–200 kg, range + number), play/scrub, Compare, Edit, form-check summary, cues and mistakes. Sheet rule from R4: collapsed = title, variation, transport, legend, one summary line; everything else in `.more`; open sheet ≤ 45vh; the body never covered.
- **R6 Compare** (user decision): pin the current version (exercise or task) as A; change to B; an A/B switch flips the body; the pinned pose is drawn as a faint translucent ghost over the current one; the sheet shows the muscle table A vs B and the differences in words (top changes by level, lumbar moment Nm, balance). At ≥ 900 px wide the two muscle columns sit side by side; below that they stack.
- **R7 Keyframe editor**: `#workouts/edit/<kind>/<id>` opens the record's keyframes in the Move screen's strip with its equipment, loads and supports; drag joints, effort and form checks update live (≤ 10 Hz); add/remove/reorder keyframes (≥ 2 kept); "Save my version" stores it on the device only (`localStorage bodyModel.edits.v1`, keyed `<kind>/<id>`), "Revert" deletes it. Storage off → edits last the visit, with a notice.
- **R8 Task builder** (SPEC §6) at `#workouts/tasks`: Object (box, bucket, bag, child, suitcase, gas cylinder, furniture edge, mop or broom, none), Weight 0–50 kg (push/pull: the force to move it, labelled "kg of force"), Start (floor in front, floor to the side, knee height, table, shelf, overhead), Action (pick up, put down, carry, push, pull, climb step, sit down, stand up, reach, bend and hold), Style (2–3 per action; pick up = stoop, squat, one-hand, golfer's lift). Keyframes generated from data templates + two-bone IK to the start location + balance fix (user decision); combinations without a template are disabled with the reason. Presets = the 5 old tasks (bucket stoop/squat/one-hand, carry one/both, mop, shelf, stairs) as builder settings; tasks.json retires. Outputs: per-muscle effort (effort panel), lower-back moment in Nm with a low/medium/high band and the note "overcounted: trunk mass sits on one spine bone (known gap)", balance warning when the centre of mass leaves the feet. Edit → editor (R7). Compare → R6.
- **R9 Wrist start values** reviewed (known gap): find a published wrist flexion/extension torque source, update strengths.json with it, or keep the value and state "not verified" in the report with why curls show wrist/finger flexors on top.
- **R10 Measurements** at the checkpoint: contact sheet of all 50 (male and female), form-check table (0 failing), stoop vs squat numbers, one-hand vs split carry numbers, APK bytes, desktop fps, phone fps if a device is attached (none attached at plan time → "unmeasured" otherwise).

## 2. Context for the builder
```
- Builder: do your tasks in order. Tick [x] only after the task's verify passes.
  In a parallel wave you do not tick; report the task as verified and main ticks.
- Builder: touch only the task's files. Need another file or a dependency?
  Stop and report.
- Builder: never edit a test from an earlier task to make it pass.
  If a test looks wrong, report it.
- Tester: run TEST_PLAN.md only. Record results in TEST_RESULTS.md. Fix nothing.
- All: reply to main in ≤10 lines. Details go in files.
```
Decisions: branch r5-library-tasks, builders don't commit; no new deps; data in JSON with `sources`; `src/engine/` pure (no three.js), every rule tested; `src/library/` pure too (no three.js, no DOM) so form checks and the task generator are testable; no hand-written muscle lists anywhere (an exercise adds keyframes + props only); medical wording education only, every on-screen claim sourced; phone first 390×844; nothing personal leaves the device (edits and body mass stay in localStorage); free assets only, source + licence recorded.
R4 binding decisions hold (r4-effort-engine plans/PLAN.md §2b): engine API `effort`, `effortOverMove`, `setupVariant`, `supportPin`, `loadEngine`; sideless joint keys; pins (`default`=flat for supports, `toes`, `toeL/R`, `none`, `hands`); `variantProps` is the only per-record support entry; a new prop needs a loads.json and a supports.json entry (or a `none` listing); sheet layout rule.
Conventions: TypeScript strict; Vitest tests next to source (`*.test.ts`); `h()`/`btn()` helpers as in `src/ui/workouts/player.ts`; data tests read `public/data/*.json` with readFileSync (`src/library/data.test.ts` style); SI units; prototype coordinates (metres, ROOT_Y 0.965) × body scale `s = pelvis rest height / 0.965` for fixed equipment, as `props.ts`.
Reference code: `src/ui/workouts/player.ts` (sheet, transport, colours, loads, live panel), `src/ui/workouts/props.ts` (placement and hand-held follow; replaced by equipment.ts), `src/ui/workouts/move.ts` (keyframe strip, handles, IK, undo, localStorage pattern), `src/engine/setup.ts`, `src/engine/effort.ts`, `src/rig/pose.ts` (`fromPrototype`, `lerpPose`, `clampPose`), `src/rig/ik.ts` `solveTwoBone`, `src/rig/skin.ts` (bone texture, SKIN_GLSL), `src/body/scene.ts` (`addOverlay`, `setPose`), `tools/engine/shots.mjs` (`--shot <sex> <route> <out.png> [js]`, headless Chrome, dev server on 5300).
Gotchas: keyframes stay ProtoPose (prototype format) in data; the editor works on `Pose` and saves `Pose[]`; `supportPin(proto)` not `fromPrototype(...).pin` for supports; pinAt is in prototype coords (scale by s); `setupVariant` key changes from `exercise/variant` to the record id (T1 renames `towardByVariant` and `variantProps` keys); trunk mass on spine_02 overcounts the lumbar moment (say so where the band shows); skinning tears at extreme shoulder poses and folds at hip/elbow/knee (R3): do not fix unless a reviewed pose needs it, record any tile that shows it; `make apk` needs `PATH=$HOME/.nvm/versions/node/v24.15.0/bin:$PATH`; Vitest summary reporter crashes on Node 20 (use Node 24 or `--reporter=json`).

Pattern names are SPEC §5's list plus `hold` and `carry`; `crunch` uses pattern `flexion` added to the list (SPEC §5 updated in T14).
3. **Equipment placement**: `equipment.json` item = `{ id, name, kind: 'fixed'|'handheld', parts (built-in model recipe name + dimensions in metres), at (default prototype-coord position, yaw), adjust? (e.g. bench `angle` −15..85°), surfaces: [{ name, support point it carries (seat→pelvis, bench→thoraxBack/pelvis, pad→forearm/shin, floor), plane: point + normal in item coords, extent }], colliders: [{ box|capsule in item coords }], grip?: points for handhelds, source, licence }`. A record may override placement per item: `placement: { <item>: { at?, yaw?, angle? } }`. Rendering (`src/ui/workouts/equipment.ts`, three.js) and form checks (`src/library/form.ts`) both read this file; colliders and surfaces are the same numbers the mesh is built from.
4. **Props vs equipment**: the engine still reads `props[]` through loads.json/supports.json. A record's `props[]` lists engine props (loads/support pseudo-props such as `floorHands`, `matSupine`); `equipment[]` lists what is drawn (equipment.json ids) and is the filter facet. `equipmentProps` in equipment.json maps an item to the engine props it implies when the record lists none (e.g. `seat`); the record may list props explicitly. A new engine prop gets loads.json and supports.json entries (or a `none` listing) in the task that first needs it.
5. **New engine body points/loads** (T2): body points `hipsFront` (pelvis head + 10 cm along body +z: hip-thrust bar, glute bridge), `chest` (spine_03 midpoint + 12 cm along +z: prone contact), `knee_l/r` (knee joint centre + 5 cm along body +z: front of the knee, kneeling contact), `elbow_l/r` (elbow centre: side plank forearm contact uses `forearm_*`), `shoulderBack` (spine_03 head − 12 cm along z: hip-thrust bench edge, glute-bridge floor). Load kind `band` = elastic: force toward its anchor, magnitude = kg × g at the stretched keyframe (simplification, noted in loads.json `note`). Offsets are in the body frame of the bone (+z forward, +y up); each new point and kind has a test asserting the offset. Band anchor = direction in loads.json `towardByVariant[<record id>]`, as `handle`.
6. **Form check sampling**: keyframes k0..kn and 3 in-betweens per segment (t = .25, .5, .75 of `lerpPose`); balance uses the record's supports via `setupVariant(id, props, supportPin(kf), tables)`; `contacts` only for support points whose equipment item exists in the record; hand-held items follow the hands so only `clearance` vs floor applies to them.
7. **Compare words** (`src/library/compare.ts`): rank muscles by |levelB − levelA| ≥ 0.1, max 6 lines: "<Muscle> (<side>) rises from low to high" with level bands low < 0.25 ≤ medium < 0.5 ≤ high; lumbar moment "Lower back: 62 → 31 Nm (−50%)"; balance change; "No muscle changes by more than 10%" when none.
8. **Ghost** (`viewer.setGhost(pose | null)` in scene.ts): a second draw of the skin geometry with its own bone texture and a translucent material (opacity 0.18, depthWrite false, renderOrder after skin), same SKIN_GLSL; no picking; disposed on null. Cost: one extra skin draw only while comparing.
9. **Task generator** (`src/library/taskgen.ts`, data `public/data/taskbuilder.json`): `generateTask(settings, rig, sex, tables) → { keyframes: Pose[], props, loads, supports, warnings } | { disabled: reason }`. Steps: (1) template keyframes for action × style (ProtoPose in data, with `free` = which DOFs reach the target: stoop → hip + spine flex, squat → hip + knee + ankle with trunk ≤ 20°, one-hand → stoop with one arm and contralateral hand on knee, golfer's → stance hip flex with the other leg extended back); (2) hand target from start (`floorFront`, `floorSide`, `knee`, `table` 0.75 m, `shelf` 1.5 m, `overhead` 1.9 m, in prototype coords × s; forward 0.3 m) and the object's grip height; (3) iterate the `free` DOFs (bisection on one scalar per style) until the grip point height is within 3 cm, then arm two-bone IK to the grip; (4) balance fix: shift root z and ankle flex together until `balance.margin ≥ 0` (max 15 cm / 15°; else `warnings` "cannot balance this pose" and the combo stays playable with the balance warning shown); (5) load = object kg at hands (both or one per style; carry one-hand → `hand_r`); push/pull = horizontal `cable` toward/away along body z at hand height. Actions: put down = pick up reversed; sit down/stand up use the `chair` object as support (pin none at the seated keyframe); climb step uses `step1`; reach = arm raise to start target, standing; bend and hold = the pick-up bottom keyframe held (no poseB). Combos: see 2c.7.
10. **Lumbar band**: `lowerBack.level` (moment ÷ typical back-extensor strength, strengths.json source) → low < 0.3 ≤ medium < 0.6 ≤ high. Label: "Share of typical back-extensor strength (estimate)". No injury threshold is claimed.
11. **Reviewed**: `reviewed: true` = all checks pass on both sexes and T13 sets it: the T13 builder opens each contact-sheet PNG with the Read tool (images), compares the tile with the cues and writes one line per tile in plans/raw/review.md; T9a/T9b leave `reviewed: false`. The user's checkpoint review is the final say.
12. **Routes** (T5 owns `src/ui/shell.ts`): `#workouts/exercises`, `#workouts/exercises/<id>`, `#workouts/edit/<kind>/<id>` (kind = exercises|tasks; tasks id = `custom` reads the builder's current settings from sessionStorage), `#workouts/tasks` (builder), `#workouts/tasks/<preset>`. Old `#workouts/exercises/<old>/<variant>` links map through the 2b.1 table.

### 2c. Critic round 1 clarifications (binding)
1. **Closed enums.** `pattern` ∈ curl, press, row, pulldown, squat, hinge, lunge, raise, fly, extension, rotation, carry, hold, flexion. `posture` ∈ standing, seated, incline, decline, lying, kneeling, hanging. 2b.2 rows map: chin-up, pull-up → pulldown/hanging; face-pull → row/standing; band-pull-apart, rear-delt-fly → fly/standing; lying-leg-curl → curl/lying; crunch → flexion/lying; pallof-press → rotation/standing; bench-dip → extension/seated; one-arm-dumbbell-row → row/kneeling; bulgarian-split-squat, step-up → lunge/standing; hip-thrust → hinge/lying; side-plank → hold/lying; leg-extension → extension/seated. Extra detail (rear foot on bench, one knee on bench) goes in `note`.
2. **formChecks and loads keys.** Record `formChecks` ids ∈ `kneeOverFoot`, `neutralSpine` only (params: `neutralSpine {maxLumbarFlex: number}`); the global checks run for every record and are not listed. Record `loads` keys = engine load ids (the prop names or `prop#i`) with kg values; the data test rejects unknown ids and unknown check ids.
3. **Compat during the build.** The app stays working after every wave: T1 keeps the old routes alive (2b.1 map in `legacyId`), tasks.json and the old task player path stay until T12.
4. **Equipment.json ownership.** T3 creates the file with `items` and `objects` (chair, step1, step2); T4 adds the remaining objects (different waves).
5. **Equipment smoke.** T3 has no render check; the render proof is T4's `tiles: N of N` and the user gate. A rejected item goes back to a T3/T4 fix round.
6. **Task combos and targets** (`taskbuilder.json` `actions[]` carries `objects`, `starts`, `target`): pick up / put down: any object except none; starts floorFront, floorSide, knee, table, shelf, overhead; target = grip point at the start height ± 3 cm. carry: any object except none; start n/a; target = grip point at 0.85 m × s (hand hang). push / pull: furniture edge only; start n/a; target = hands at 1.0 m × s, 0.4 m ahead; load = horizontal `cable` of `kg` along ±z at the hands. climb step: object none; target = lead foot on `step1`. sit down / stand up: object none; target = pelvis at the `chair` seat height (0.45 m × s) ± 3 cm. reach: none or box/bag/bucket; starts table, shelf, overhead; target = grip point at the start height. bend and hold: any object; starts floorFront, knee; target = the pick-up bottom keyframe grip point; no poseB. Every other combination is disabled with a reason string. The builder confirms the plain muscle names used by the acceptance tests (obliques, quadratus lumborum, gluteus medius) exist in actions.json before asserting on them.
7. **T8 sizing**: stays L; if the builder cannot finish, split into T8a generator core and T8b templates for the remaining actions.

### 2d. T9a blocker decisions (binding)
A. **Scaled root.** `protoToPose(proto, s)` is exported from src/library/exercises.ts: `fromPrototype` plus root x/y/z and pinAt scaled by the body scale `s` (pelvis rest height / 0.965). form.ts, tools/library/check.mjs and (in T12) player.ts and the editor use it; the female no longer sits lower on the same seat.
B. **Floor counts as a surface.** `checkContacts`: a foot or heel support point is satisfied by the floor (y = 0 ± 3 cm) as well as by an equipment surface.
C. **Back of pelvis.** New body point `pelvisBack` (pelvis head, 8 cm along body -z, 4 cm down) in geometry.ts with a test; the bench and reclineSeat lying contacts use it (equipment.json surfaces and supports.json); the seated bench keeps `pelvis`.
D. **Plank.** Plank drops the mat (bodyweight, like push-up); side-plank (T9b) uses the mat with forearm contacts and the floor rule of B.
E. **Braced balance.** `checkBalance` is skipped when pin is `none` and a seat, back, bench or pad support exists (the equipment braces the body, no standing balance); the check still runs for every standing, plank, push-up and hang record. leg-press gets its sled load.
T9a file list gains: src/library/form.ts, src/library/exercises.ts, src/engine/geometry.ts, src/engine/geometry.test.ts (add tests only), public/data/equipment.json (surfaces only).

## 5. Data models
`Exercise = { id, name, family, aliases: string[], pattern, posture: 'standing'|'seated'|'incline'|'decline'|'lying'|'kneeling'|'hanging', equipment: string[] (equipment.json ids or 'bodyweight'), bodyParts: string[] (Arms, Shoulders, Chest, Back, Legs, Glutes, Core, Calves), props: string[], placement?: Record<item, {at?, yaw?, angle?}>, loads?: Record<loadId, kg>, keyframes: ProtoPose[] (≥ 2), cam?: {az}, cues: string[], mistakes: string[], formChecks: { id, params? }[], note?, sources: string[], reviewed: boolean }`.
`taskbuilder.json = { sources, objects: [{ id, name, kg, grip: 'both'|'one'|'edge', size: [w,h,d], model, simplified? }], starts: [{ id, name, height, forward, side }], actions: [{ id, name, styles: [{ id, name, keyframes: ProtoPose[], free: string, hands: 'both'|'right', support?: string }] , objects: string[], starts?: string[] }], presets: [{ id, name, settings }] }`.
`equipment.json` per 2b.3; every item `source: "built for the project"` and `licence: "ours (project licence)"` unless a CC0 glTF replaces it.
