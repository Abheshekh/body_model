# R2: Body page (report)

Branch `r2-body-page`. The sample's Body page rebuilt as app code on the R1 data, both sexes, phone / tablet / desktop. Numbers are measured (plans/raw/measure.md, `npm test` run for this report).

## 1. What was built
- **Body page** (`src/ui/body/`, `src/body/`): one WebGL viewer, one mesh per pack, state texture, GPU-decoded quantised positions. Depth slider (Skin, Outer, 2 to 6, Bones), systems toggles, see-through skin, ghost peeled, colour modes with legend, skin tones light / medium / dark, labels (GPU id pass, leader lines), list with tabs, grouping, search and dimmed peeled rows, part card (fields, "simplified" note, sourced facts, Isolate, Hide, Zoom to it, Show hidden). Tap a part or a label to select.
- **Facts** (`public/data/facts.json`): 100 parts keyed by plain name (applies to both sides), 2 to 4 facts each, each with an OpenStax URL checked with curl (plans/raw/facts-urls.log).
- **App shell**: Body, Workouts, Me. Bottom tab bar on phone, top bar on wide. Hash routes `#body`, `#workouts`, `#workouts/programs[/<id>]`, `#me`, `#me/credits`. The viewer is created once and kept.
- **Programs on the new body**: targets renamed to R1 plain names, highlight yellow with glow, peel to the deepest needed layer, pelvic items isolate the pelvic-floor muscles with bones at 25% and a view from below. Programs show on the profile's sex and restore the Body state on exit.
- **M1 removed**: `explore.ts`, `viewer.ts`, `body.glb`, `parts.json`, `credits.json`, M1 pipeline files. `npm run pipeline` and `test:pipeline` point at v5. Credits read `data/body/credits.json` and the `facts.json` sources.

## 3. Numbers
Headless Chrome (new headless), **software GL (SwiftShader/ANGLE)**, 1440x900, Vite DEV server (unminified). Not a GPU and not a phone; relative use only.

| Measure | Skin | Outer |
|---|---|---|
| Body load time (male) | 2856 ms | 3054 ms |
| fps (`?fps=1`, 5 x 1 s samples after 12 s settle) | 5, 5, 5, 5, 6 | 4, 4, 4, 4, 4 |

- APK (`make apk`, debug): `output/body-model-debug.apk` = 20,067,991 bytes (19.1 MiB).
- Tests (`npm test`): 7 files, 106 tests, all pass.
- The main session also opened the app in the built-in browser on a real GPU (ANGLE Metal, Apple M4 Pro); the pane was hidden so frame timing was throttled and no fps was recorded.
- **Phone fps and load time are not measured.** No device was connected. The ">= 30 fps on the phone" target is open until the manual check below.

## 4. Decisions
Plan section 2b:
1. M1 files deleted only after Programs ran on the new body.
2. Routes owned by `parseRoute` in `src/programs/programs.ts`; unknown hash goes to Body.
3. Isolate is a set: shown if in the set, or a bone with skeleton on (context); the rest hidden. Bones draw at 25% during an isolate.
4. Groups by plain name: list rows, select, Hide, Isolate, Zoom and card act on every id sharing the plain name (left and right). Facts keyed by plain name.
5. `Part`, `Manifest`, `PackData` live in `load.ts`.
6. PackData typed-array views as in the plan; `mid` is a float attribute.
7. Initial state from `defaultState(m, sex)`.
8. State texture 64x128 RGBA8 (visibility, highlight, isolate, colour mode colour).
9. Part bounds computed on the CPU per sex; facing for programs from the targets' centre z.
10. `createBodyViewer(canvas, {fps})` resolves after the first frame; load failure shows "Could not load the body: <reason>".
11. DEV hooks (`depth`, `sex`, `open`, `part`, `window.bodyViewer`) only under `import.meta.env.DEV`.
12. Screenshot script `tools/shots/cdp-shot.mjs`.
13. Screenshot names `<w>-<sex>-<depth>.png`.
14. Program targets mapped to plain names; `puborectalis` maps to `Pubo-analis muscle` (closest Z-Anatomy levator ani part); `multifidus` is every part whose plain name contains it; left/right collapse to one plain name.
15. Banner: female profiles see "Female anatomy here is adapted from the male model; pelvic organs are simplified."; male profiles see none.
16. Programs snapshot and restore the Body state and set the view sex to the profile's.
17. The sex switch is a view toggle initialised from the profile; it does not write the profile. Sex-only parts follow the viewed sex.
18. Credits list `data/body/credits.json` and the facts sources.
19. Tasks split T4a/b, T6a/b, T2b, T8b.

Changelog decisions:
- Tablet sheet layout: bottom sheet below 900 px wide (768x1024 gave a 428 px canvas and cut labels).
- Colour legend sits under the depth slider on phone.
- Isolate set (see 3 above); groups by plain name (see 4).
- Labels under 8 characters after truncation are dropped; label area threshold tuned to reach >= 8 labels at 1440x900 (SPEC says up to 14).
- A tendon pick counts as muscle class. Selection uses the highlight channel (same yellow glow). `frameIds` waits for demand packs. Card test part is Long head of biceps brachii (no single biceps part).
- `setSkinTone(light|medium|dark)` added; DEV `open` / `part` hooks belong to the page.
- Tensor fasciae latae is not in the Z-Anatomy data: dropped from side-lying-hip-abduction targets, with the item note "Tensor fasciae latae is not in this anatomy model."
- Vertical part of longus colli maps to `Longus colli muscle`.
- `puborectalis` maps to `Pubo-analis muscle`.
- **Licence**: facts cite OpenStax *Anatomy and Physiology 2e*, licence as stated on its pages: **CC BY-NC-SA 4.0**. Facts are our own short paraphrases with a citation; no text copied. The app is free, but the NC clause must be checked before a Play Store listing (PLAN section 8).

## 5. Known gaps
- Z-Anatomy names the trapezius parts ascending / descending; the list shows those names.
- Tensor fasciae latae is missing from the data (PLAN section 10).
- Labels are cut with an ellipsis at 390 px ("Sternocostal head of...").
- The open list sheet covers most of the body while open, by design; it is collapsed by default.
- Skin tone circle row overlaps the face area at 390 (small).
- Software-GL fps (4 to 6) says nothing about phones.

## 6. Manual phone check (M4)
1. `make install` (debug APK to the phone over adb).
2. Open `chrome://inspect` on the desktop and inspect the app's WebView.
3. Add `?fps=1` to the page URL (or use the overlay in a dev build) and read the fps.
4. Targets: Outer >= 30 fps, Skin >= 45 fps.
5. Read the `Body load time: <n> ms` console line; record it.
Report the numbers to be added here.
